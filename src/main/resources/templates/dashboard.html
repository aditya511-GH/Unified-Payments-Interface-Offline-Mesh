Help center

How MeshPay works

A quick guide to the offline payment demo.

Getting started

What does offline payment mean here?

The browser encrypts a test instruction and saves it locally while disconnected. This is a simulator demonstration, not a payment network.

How are devices registered?

This version does not register personal devices. The backend provides virtual mesh nodes for demonstrating packet movement.

How do I send an offline payment?

While online, open the dashboard and let it load recipients and the public encryption key. Then select a demo account, recipient, amount and sandbox PIN 1234. When disconnected, choose Encrypt & queue; the instruction stays on this browser until you reconnect and synchronize.

What do the statuses mean?

Queued means stored in this browser. Synchronized means accepted into the backend simulator. Settled means the backend recorded a debit and credit. Rejected means backend verification refused the instruction. Only Settled is a completed demo ledger transfer.

Why is synchronization required?

The server must receive and verify the encrypted instruction before it can write a settled or rejected record to its demo ledger.

Why did synchronization fail?

Check the network connection and retry. This browser must have fetched the demo recipients and server public key while online first. The sandbox keeps its key in the backend database so queued packets survive normal service restarts.

Need a quick answer?

Queued does not mean paid. The demo cannot connect to UPI or move real funds.
